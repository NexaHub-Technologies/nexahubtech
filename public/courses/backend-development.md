## The idea this course installs: A server is a function you can call over a wire

Strip away the frameworks and a backend does one thing: it takes a request and returns a response. What makes it hard is that it does this for many people at once, and it remembers things between calls. Hold those two apart — the translation, and the state it touches — and routing, middleware, databases and auth each drop into place.

Once it lands, you can:

- Design an API by its contract before writing its code
- Separate what a request returns from what it changes
- See where two users at the same moment would break your logic
