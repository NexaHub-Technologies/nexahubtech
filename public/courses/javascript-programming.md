## The idea this course installs: The language is small; the runtime is the rest

Most of what people call JavaScript is not JavaScript. Values, functions, objects and the event loop are the language, and they are identical everywhere it runs. The DOM, fetch, the file system, timers — those are whatever the host happens to hand you. Once you can tell the two apart, moving between a browser and Node stops being a new language to learn and becomes a new set of tools around one you already have.

Once it lands, you can:

- Tell a language feature from something the host handed you
- Move the same code between a browser and Node deliberately
- Read an unfamiliar API as a runtime detail rather than a mystery

## Modules

01. **Values and how JavaScript thinks** — Primitives, objects and coercion. Why == surprises people and === does not — from the rules themselves rather than a list of things to avoid.
02. **Functions, scope & closures** — Functions as values, scope as nested boxes, and the closure — the single idea holding up callbacks, modules and most of the language.
03. **Objects, arrays & the prototype chain** — How a property lookup actually resolves. Prototypes as a chain you can follow, and the array methods that replace most of the loops you would have written.
04. **Asynchrony & the event loop** — One thread and a queue. Callbacks, promises and async/await turn out to be three views of the same machinery, which is why mixing them goes wrong.
05. **Modules and the two runtimes** — The same language in a browser and in Node. What each host provides, what it withholds, and how to write code that does not care which one it lands in.
06. **Building on both sides** — One project with a Node half and a browser half, so the split between language and runtime stops being theory and becomes something you have used.
