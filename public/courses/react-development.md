## The idea this course installs: The screen is a function of state

You don't update the page. You change state, describe what the page should look like for any given state, and let React work out the difference. Every stale value, surprise re-render and “why didn't it update?” dissolves once you stop listing the steps to change the screen and start describing what the screen is for the data you hold.

Once it lands, you can:

- Put state in the right place the first time
- Read a re-render as a consequence, not a mystery
- Delete the effects you never needed

## Modules

01. **How React actually works** — Rendering, reconciliation, and why the screen updates when it does — the model behind the API.
02. **State, placed properly** — Where state belongs, when to lift it, and how to design it so whole classes of bugs stop existing.
03. **Effects & the outside world** — Data fetching, subscriptions, and cleanup — plus learning when you don't need an effect at all.
04. **Composition & custom hooks** — The patterns that keep components small and share logic without tangling a codebase.
05. **Performance, measured** — Memoisation, list rendering, and profiling. Making it fast on evidence rather than on instinct.
06. **Architecture at scale** — Structure, data layers, and testing — the decisions that decide whether an app ages well.
